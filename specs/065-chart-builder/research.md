# Research: Chart Builder (Explore v2)

Sources: `project-docs/CHART-BUILDER-PROPOSAL.md` (external research on Graphic Walker, gropaul/dash, Vega-Lite, Plot,
DuckDB), plus a read of the repo during planning. **[V]** = verified in repo or primary source; **[U]** = unverified, owned
by a spike below.

## Decisions

### D1 — Render core shared by two hosts (not an extension of `ChartPanel`)
- **Decision**: a pure `renderChart(el, { spec, rows, theme, width, height, state })` in `src/charts/builder/compile.ts`.
  Host 1 = `explore/BuilderChartHost.tsx` (Explore preview). Host 2 = `charts/kinds/custom.ts` (YAML tiles; rows fetched in
  the kind's `loadExtra`, handed back as `env.extra`).
- **Rationale**: `ChartPanel` is built around per-run logical tables, compare/reference/year state and an "empty if no
  scenarios" gate [V `ChartPanel.tsx`]. A builder chart's data is an arbitrary relation, so forcing it through that path
  adds special cases to every curated chart. A shared pure core keeps both hosts thin and the look identical (same
  `readChartTheme`, `armPlot`, `tooltip`, `ChartLegend`).
- **Alternatives**: (a) generic kind only, rows via `loadExtra` (couples Explore to compare state); (b) a second parallel
  chart engine (rejected — breaks "looks identical").

### D2 — Spec is Vega-Lite-shaped, name-based, one schema everywhere
- **Decision**: see `contracts/chart-spec.md`. Fields by column name, never generated ids; `size` is a named scale;
  a `version` field; JSON Schema is the validator for import and YAML.
- **Rationale**: Graphic Walker's verbose generated-id spec is hard to hand-write and diff [V research]. Vega-Lite's
  encoding vocabulary is established and trimmed to what Plot can draw.
- **Alternatives**: GW `IChart` (verbose, versioned by library), a Plot-options-shaped spec (couples users to Plot).

### D3 — Aggregate, bin, filter and time-unit in DuckDB
- **Decision**: `specToSql` compiles the spec against the chosen relation to a single `SELECT … GROUP BY …`; the browser
  only maps rows to marks. Raw-point charts get `LIMIT 50000` and a visible "showing N of M" notice (M from a count run
  on demand).
- **Rationale**: scales to the large tables, matches the user's "DuckDB wherever possible", avoids shipping rows.
- **Alternatives**: Plot `group`/`bin` transforms (kept only for histogram bin edges when SQL binning is not used).

### D4 — Relation naming and temp objects
- **Decision**: saved results are `CREATE OR REPLACE TEMP VIEW "xb_<slug>" AS <guarded SELECT>` generated by the app; user
  SQL is **read-only**. `TEMP TABLE` (materialize) is an option on save with a size warning.
- **Rationale**: the user never submits DDL, so the guard needs no new "modify" surface. A TEMP object shadows a same-named
  app view (temp schema searched first), so the reserved `xb_` prefix plus the existing protected-name check prevents
  hiding `{scenario}__{metric}` views [V `catalog.ts#protectedNames`, subagent finding].
- **Cross-feature impact [V]**: the AI assistant's `resetSessionData()` drops every non-protected table/view
  (`sqlRunner.ts`), which would silently delete My tables. Add `xb_*` to its exemption, and to the assistant's
  protected names so it cannot overwrite them. Covered in `contracts/query-and-guard.md`.

### D5 — Reuse `authorize()` and the `runSql` pattern
- **Decision**: reuse `sqlGuard.authorize(sql, 'read-only', protectedNames())`; copy `sqlRunner`'s wrap-with-LIMIT, Arrow
  cell conversion and abort→`cancelRunning()` handling into `explore/sql/runUserSql.ts` (or generalise `runSql` — decide
  in tasks); add a module-level mutex and a 60 s timeout that calls `cancelRunning()`.
- **Rationale** [V]: `authorize` already refuses INSTALL/LOAD/ATTACH/COPY/SET/PRAGMA/remote URLs; `runSql` shows the
  approved wrapping and conversion. Because the connection is shared, `cancelRunning()` cancels whichever statement is
  active, so Data-tab runs must be serialized and the user told when other work is in flight.

### D6 — Two-way SQL sync via `json_serialize_sql`, with fallback
- **Decision**: builder→SQL generates canonical text from a small query model. SQL→builder calls `json_serialize_sql`
  and a pure `astToModel()` returning `null` for anything unsupported (then the form is disabled, "edited as SQL").
- **Evidence**: the AI assistant already calls `json_serialize_sql` in `sqlRunner.ts#parserSaysNotSelect` and matches
  "Only SELECT statements" in the output [V], and the function names are present in the wasm binary [V]. Whether the
  first call triggers an extension fetch, and the exact AST for each supported construct, is [U] → spike S1.
- **Fallback**: model embedded as `-- builder:v1 {…}` comment, re-imported only while the body equals the regenerated SQL.
- **Risk control**: AST is versioned with DuckDB; unit tests serialise fixture queries so an upgrade breaks a test, not
  the UI.

### D7 — Column typing
- **Decision**: `DESCRIBE <relation or query>` then `columnTypes.ts` maps DuckDB types to nominal/ordinal/quantitative/
  temporal/geo/complex; VARCHAR/BOOLEAN/ENUM → nominal; numeric → quantitative unless name matches `*_id|*_code|taz|zone`
  (→ nominal); DATE/TIMESTAMP → temporal; nested → complex (not draggable); a geometry-named BLOB → geo. Ordinal has no
  native type, so it is a user override on the chip. `catalog.ts` has no column info [V — it carries scenario and metric
  names only], so `describeView` from `sqlRunner.ts` is the base [V].

### D8 — Suggestion engine is data
- **Decision**: `rules.ts` is a table, scored like Graphic Walker's (`lib/autoViz/rules.ts` [V research]): per chart,
  dimension/measure count ranges, required types, cardinality hints, score; ties by fixed order; pie deliberately low.
  The same table drives the inverse "chart → slots" view and the greyed-out reasons.
- **Alternatives**: Draco-style constraint solving (overkill), hard-coded if/else (untestable).

### D9 — Plot gaps: dash, hatch, legend, tooltip, text
- **Dash** is not a Plot channel [V research]: compile line series into **one mark per series** with its own
  `strokeDasharray`; draw our own legend swatches.
- **Hatch**: Plot has no pattern fills. Approach A (preferred, [U] S3): an **identity colour scale** so each datum's fill is
  literally `url(#xb-hatch-k)`; the `<defs><pattern>` is inserted into the returned SVG, with pattern ink drawn from tokens.
  Approach B: one mark per series with `className`, patched after render.
- **Legend**: only the app's `ChartLegend` (`LegendSpec`); Plot's own legend covers colour/opacity/symbol only [V].
- **Tooltip/crosshair**: `title: (_d,i) => 'wfa:'+i` and `armPlot`, never Plot `tip` [V `09-chart-kind-guide.md`].
- **Text blocks**: drawn by the app (HTML above/below the plot) rather than Plot `title/subtitle/caption`, so Plot's return
  type stays an `SVGSVGElement` and `exportTile.ts` (`cardToSvg`) captures them with the same code path as curated tiles
  [V exports take a card element].
- **Pie/donut**: `d3-shape`, as `donut.ts` does today [V `kinds/donut.ts` exists].

### D10 — Drag and drop with keyboard parity
- **Decision**: `@dnd-kit/core` (already a dependency, [V package.json]) for drag; `useAssignByKeyboard` provides
  "select chip → choose channel (menu)" and arrow-key reorder within a shelf. Drop validity comes from the channel table in
  `spec.ts` so the refusal reason is the same in both paths.

### D11 — SQL editor
- **Decision**: v1 = plain `<textarea>` behind a `SqlEditor` seam (monospace token font, line numbers deferred, Ctrl+Enter
  runs). CodeMirror 6 + `@codemirror/lang-sql` is a later lazy chunk (~50–80 KB gzip [U]) and is a new dependency, so it
  needs an explicit go-ahead and is **out of scope here**.

### D12 — State and persistence
- **Decision**: `state/exploreState.ts`: plain pub/sub module (same style as `tileState.ts`) holding tabs, specs, My-table
  catalogue. No Web Storage. Export/import JSON is the only persistence. A `broken` status is derived when a My table's
  defining query fails to re-describe.

### D13 — Replacing Graphic Walker
- **Decision**: develop alongside (new panel type `explore-builder`, extra Explore tab entry on this branch). At acceptance
  (User Story 7): switch `dashboard-7-explore.yaml`, delete `GraphicWalker*` files, `graphic-walker` manual chunk, the CSS,
  `@kanaries/graphic-walker` dependency; amend constitution (Technology Stack Reference) and CLAUDE.md.
