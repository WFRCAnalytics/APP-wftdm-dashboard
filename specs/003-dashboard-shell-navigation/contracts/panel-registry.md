# Contract: Panel registry + shell/nav/card wiring

Satisfies: FR-001, FR-002, FR-003, FR-004, FR-010. Implements the registry
shape the constitution's v2.2.0 amendment already specifies.

## `panels/registry.tsx`

```tsx
export const registry: Record<string, ComponentType<PanelProps>> = {
  valuebox: ValueBoxPanel,
  plotly: PlotlyPanel,
}
```

## `layout/shell.tsx`

Top-level app shell: renders `navBar` with the discovered tab set (from
`layout/types.ts`'s parsed `DashboardTabConfig[]`) and the active tab's
`dashboardRenderer`. Active-tab selection is local component state (no new
global store needed — tab selection isn't a cross-cutting filter,
constitution Principle VI's no-Web-Storage rule doesn't apply to transient
UI state either way).

## `layout/navBar.tsx`

Wraps `002-design-tokens`' shadcn `Tabs`/`TabsList`/`TabsTrigger` — one
`TabsTrigger` per discovered `DashboardTabConfig`, labeled by
`header.tab`. No tab count/name is hardcoded (FR-001) — the list is
generated by mapping over whatever `shell.tsx` passes down.

## `layout/dashboardRenderer.tsx`

Renders one active tab's `layout` (`Record<string, PanelConfig[]>`) as
ordered rows of `panelCard`s, each panel sized by its `width` fraction
within its row (a CSS flex/grid concern, not a data concern — no new field
needed beyond `PanelConfig.width`, already in `data-model.md`).

## `layout/panelCard.tsx`

```tsx
export function PanelCard({ config }: { config: PanelConfig }) {
  const PanelComponent = registry[config.type]

  return (
    <Card className="shadow-md">
      <CardHeader><CardTitle>{config.title}</CardTitle></CardHeader>
      <CardContent>
        <PanelErrorBoundary panelTitle={config.title}>
          {PanelComponent
            ? <PanelComponent config={config} />
            : <PanelErrorState message={`Unknown panel type: "${config.type}"`} />}
        </PanelErrorBoundary>
      </CardContent>
    </Card>
  )
}
```

`PanelErrorBoundary` is a small class component (React error boundaries
require a class — no hook equivalent exists) — the one deliberate exception
to "function components only" in the panel pattern, scoped narrowly to
this single, shared, cross-cutting concern, not a precedent for panel
components themselves.

`PanelErrorState` and `PanelEmptyState` (referenced here and by
`ValueBoxPanel`/`PlotlyPanel` directly for their own empty-result cases,
`contracts/valuebox-panel.md`/`contracts/plotly-panel.md`) are shared
`panels/` components, not defined ad hoc per panel — ported from
`APP-Project-Scoresheet`'s `EmptyState.tsx` and `.banner-error` pattern
respectively (research.md §8), re-expressed in this project's own tokens:

```tsx
// panels/PanelEmptyState.tsx — mirrors EmptyState.tsx's exact prop shape
export function PanelEmptyState({ icon: Icon, message, hint }: {
  icon: LucideIcon; message: string; hint?: string
}) {
  return (
    <div className="flex flex-col items-center gap-2 py-8 text-center text-muted-foreground">
      <Icon size={28} strokeWidth={1.5} aria-hidden="true" />
      <p className="font-body text-sm">{message}</p>
      {hint && <p className="font-body text-xs text-muted-foreground/80">{hint}</p>}
    </div>
  )
}

// panels/PanelErrorState.tsx — structure ported from .banner-error (icon +
// message + role="alert"); background is the flat card surface with a
// destructive border, not Scoresheet's dedicated tinted-background token
// (research.md §8 explains why: no WCAG-verified equivalent exists yet in
// 002's token set, and adding one speculatively would copy a value without
// copying the verification behind it)
export function PanelErrorState({ message }: { message: string }) {
  return (
    <div role="alert" className="flex items-center gap-2 rounded-md border border-destructive p-3 text-sm text-destructive">
      <TriangleAlert size={18} aria-hidden="true" />
      <span className="font-body">{message}</span>
    </div>
  )
}
```

## Given/When/Then

- **Given** the discovered dashboard-config set has N tabs, **when**
  `shell.tsx` renders, **then** `navBar` shows exactly N `TabsTrigger`s
  and `dashboardRenderer` renders only the active one's content (FR-001,
  FR-002, SC-001).
- **Given** a panel's `type` has no registry entry, **when**
  `panelCard.tsx` renders it, **then** it shows a scoped "unknown panel
  type" message inside that one card — the rest of the tab renders
  normally (FR-010).
- **Given** a panel component throws during render (not just a rejected
  query promise), **when** `panelCard.tsx`'s error boundary catches it,
  **then** only that card shows an error state — sibling panels and the
  rest of the shell are unaffected (FR-010, SC-006).
- **Given** every rendered panel card, **when** its DOM is inspected,
  **then** it carries `002`'s `shadow-md`/`border` tokens (SC-004) — not
  an unstyled default `<div>`.

## Non-goals for this feature

- No drag-to-reorder, resize, or panel-add/remove UI — layout is entirely
  config-driven, read-only from the UI's perspective.
- No nested/recursive layout (rows of rows) — `project-docs/GRAMMAR.md`'s `layout`
  is one level of named rows, each a flat list of panels.
